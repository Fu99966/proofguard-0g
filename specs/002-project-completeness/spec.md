# ProofGuard project completeness

The operator adopted the 2026-11-18 completeness plan for ProofGuard and selected a full trading agent for phase three. The firewall stays independently authoritative over what the agent can execute. Use Base Sepolia for transaction submission and production acceptance before any mainnet plan.

- FR-001 Require canonical EVM transaction inputs. Decode allowlisted token, Permit2 and Universal Router calls. Block unsupported semantics, inconsistent legacy claims, unsafe recipients, source accounts or allowances, and missing independent valuation evidence.
- FR-002 When the operator explicitly enables dual-model review, give both independent 0G reviewers the trusted owner mandate and decoded effects. Label proposer memo as untrusted and exclude deterministic votes from both prompts.
- FR-003 Require authenticated, rate-limited Agent review, restricted CORS, durable SQLite permits and decision records, atomic consumption, EIP-712 signatures and PR CI. Retain a zero-cost, clearly marked public demo.
- FR-004 Deliver a guarded SDK, custom calldata UI and Base Sepolia trading agent with independent market inputs, strategy, portfolio state and review-first execution.
- FR-005 Enforce permits on a Safe, restrict the agent role, simulate balance changes and test missing, expired, replayed and modified permits. Verify on testnet before any mainnet operation. Third-party audit is a mainnet release gate.
- FR-006 Run a labeled repeatable evaluation and report measured recall and false-positive rate with sample size and scope.
- FR-007 Verify two hours live on Base Sepolia with a separate limit of 30 Router requests and USD 0.90, reserved before transmission at the maximum possible charge. In order, verify 20 minutes in range, a test USDC deposit and guarded swap, an untrusted tool result blocked without a Permit, 10 minutes of RPC loss and recovery, restart continuity without a duplicate Permit, and a locally rejected reservation. Missing Permit evidence, inconsistent charges, or a failed reservation guard terminates the run.
- FR-008 Observe Base Sepolia read-only for 24 hours. Record at least 95% successful scheduled samples, RPC and quote recovery, memory measurements, and positions that would require review. No Router requests or transaction signing. Deliver separate live and read-only reports. Add at least five sourced Base Sepolia swaps.
- FR-009 Enforce the Base Sepolia portfolio mandate for swaps using independently projected exposure. Reject transactions inside the band, steps that fail to reduce distance to 40%, and steps crossing the opposite boundary. Verify all fifteen blocked cases and five positive controls offline. Measure fifteen distinct samples with a separately authorized live committee budget, divided into visible-rule and blind groups with both labels in each.
- FR-010 Issue a short-lived Permit when all deterministic checks pass in the default mode. Run without a 0G key and make zero Router requests. In explicitly opted-in mode require both reviewers' valid `ALLOW` decisions and two Router-confirmed TEE receipts. Display and bind the chosen mode in each Permit. Refuse a Permit whose metadata changes after signing.
- FR-011 Deliver a loopback-only local installation by default. Warn on a non-default bind address, retain access control and rate limits, and exclude local environment files, credentials and data from Git and installation packages. Verify a new clone using the documented Node version and local commands.
- FR-012 Prepare a design for document-triggered dual-model review, including an Owner `REVIEW` queue, verifiable chain-off evidence and prompt-injection defenses. Implement after operator approval.
- FR-013 Freeze the unchanged Guard with audit tests under the deployed Solidity compiler. Exercise both hooks and recovery against genuine Safe v1.5.0 on a Base Sepolia fork. Test the absence of valid Permits as an invariant. Target at least 80% branch coverage and explain residual uncovered branches. Regenerate the audit package after verification.
- FR-014 Add owner-quorum recovery to the next Guard. One Safe transaction pauses the Agent, rotates the issuer, advances the Permit epoch and emits an event. Neither the Agent nor issuer alone can recover. Previous signatures and staged owner Permits become invalid. Verify loss, compromise, insufficient quorum and prior-epoch replay on a Base Sepolia fork. Maintain 100% Foundry branch coverage. Document and estimate migration before any testnet deployment.
